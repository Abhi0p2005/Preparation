2. Transactions & Isolation

Isolation levels & anomalies

LevelAnomalies allowed
Read Uncommittedall (dirty, non-repeatable, phantom)
Read Committedno dirty read (still non-repeatable, phantom)
Repeatable Readno dirty / non-repeatable (still phantom)
Serializablenone (phantom fixed by range locks)
  • Dirty read — reading uncommitted data that may roll back.
  • Phantom read — same range query twice; another TX inserts a row. Fixed by range locks / Serializable.
  • Lost update — two TX read the same value and both write stale. Fix: locking or version check (MVCC).
  • MVCC — multiple row versions; readers see a snapshot, writers make new versions → no blocking.
  • 2PL — growing (acquire) then shrinking (release) phase. Strict 2PL holds write locks till commit.
  • WAL — log written BEFORE the data change. Recovery: REDO committed, UNDO uncommitted.
  • Default isolation: MySQL = Repeatable Read, Postgres = Read Committed.

3. Indexing & Performance

Index typeO(log n)Use
B+ treerange/equality/sort, linked leavesmost indexes
HashO(1) equality onlyexact-match lookups
  • Clustered = rows physically ordered by key, 1 per table. Non-clustered = key + pointer to row, many allowed.
  • Leftmost prefix rule: INDEX(a,b,c) needs a first, then a+b, then a+b+c. WHERE b=5 alone can't use it.
  • When an index is NOT used: function(col), LIKE '%x', cast(col), low cardinality, small tables.
  • Cardinality = number of distinct values. Low cardinality (gender, status) → index barely helps.

RAID / Replication / Sharding

  • RAID: 0=striping · 1=mirror · 5=striping+parity (1 fail) · 6=dual parity · 10=mirror+stripe.
  • Sync replication = no loss, higher latency; async = faster, possible loss.
  • Sharding: hash (even, no range), range (range queries, hot spots), directory (flexible, extra hop).
  • OLTP = many small normalized transactions; OLAP = big denormalized analytical queries (star schema).

4. OOP — Four Pillars (with banking examples)

PillarMeaningExample
Encapsulationbundle data + methods, hide internal state (private fields)BankAccount keeps balance private; only deposit()/withdraw() change it
Inheritanceclass inherits fields/methods from parentSavingsAccount extends Account
Polymorphismsame name, different behaviourdraw() renders Circle vs Square; toString() works on any object
Abstractionhide implementation, expose only what's neededuse a remote without knowing the circuits
  • Encapsulation vs Abstraction: encapsulation hides DATA (private fields + accessors); abstraction hides IMPLEMENTATION (interface vs concrete).
  • Overloading — same name, different params, compile-time. Overriding — subclass reimplements parent, runtime (via vtable).
  • Abstract class — state + concrete methods, single inheritance. Interface — contract, multiple implements, default/static methods (Java 8+).
  • Inheritance vs Composition: IS-A vs HAS-A. Favor composition (loose coupling, swappable, mockable).
  • Liskov violation example: Square extends Rectangle — setWidth(5)+setHeight(10) breaks area()==50. Subtype must honor the base contract.

6. Java Internals

  • HashMap internals: array of buckets; get/put via hash(key); collisions → chaining (linked list → tree past 8); resize at load factor 0.75 (rehash, O(n)).
  • equals/hashCode contract: if a.equals(b) then a.hashCode()==b.hashCode() MUST hold — override both together or HashMap breaks.
  • ConcurrentHashMap vs synchronizedMap: CHM = CAS, lock-free reads, per-bucket locks; synchronizedMap = single global lock, serializes everything.
  • volatile vs atomic: volatile = visibility only, NOT atomic; AtomicInteger = CAS, thread-safe counters.
  • fail-fast vs fail-safe: fail-fast throws ConcurrentModificationException; fail-safe iterates a snapshot.
  • Why String is immutable: security, thread-safety, String pool caching, safe hash caching.
  • StringBuilder vs StringBuffer: both mutable; StringBuilder not thread-safe (fast), StringBuffer synchronized (slow).
  • transient: skips the field during serialization.
  • try-with-resources: auto-closes AutoCloseable. Yes, try without catch is legal (try-finally).
  • Record (16+): immutable data carrier — auto constructor, getters, equals, hashCode, toString.
  • Checked vs unchecked: checked must be declared/handled (IOException); unchecked = runtime (NullPointer, Arithmetic).
  • ExecutorService: FixedThreadPool(n), CachedThreadPool (grows), ScheduledThreadPool — reuse threads.
  • CompletableFuture: supplyAsync().thenApply().thenAccept() — async pipeline, avoids blocking.
  • effectively final: not declared final but never reassigned — required in lambdas/anonymous classes.
  • GC generational heap: Young gen (minor GC — most die young) → Old gen (major GC). Never force GC.
  • Deadlock in Java — avoid: consistent lock ordering, tryLock with timeout, single lock.

7. Flashcard Essentials (DBMS + OOP + Java)

1NF / 2NF / 3NF / BCNF?

1NF atomic values · 2NF no partial dep · 3NF no transitive dep · BCNF every determinant is a candidate key.

DELETE vs TRUNCATE?

DELETE = DML, rollback-able, fires triggers, slow. TRUNCATE = DDL, can't rollback, no triggers, fast.

Overloading vs overriding?

Overloading = same name, different params (compile-time). Overriding = subclass reimplements parent (runtime, vtable).

HashMap vs HashTable?

HashMap not synchronized, allows null; HashTable synchronized, slower.

Volatile vs atomic?

volatile = visibility only, NOT atomic. AtomicInteger = CAS, thread-safe counters.

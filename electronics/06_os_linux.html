1. OS Basics & Process vs Thread

OS layers: Applications → Libraries (libc) → Kernel → Hardware. Kernel mode = full hardware access; user mode = restricted; apps request services via system calls.

4. Synchronization & Deadlock

  • Race condition: two threads access shared data; result depends on timing. Fix: lock the critical section.
  • Critical section requirements: mutual exclusion, progress, bounded waiting.
  • Mutex: ownership (only locker unlocks), priority inheritance. Semaphore: counter, no ownership, binary (signal) or counting (N resources).
  • Priority inversion: low task holds lock a high task needs while mediums run → high starves. Fix: priority inheritance.

Deadlock — 4 necessary conditions (ALL must hold)

  1. Mutual exclusion
  2. Hold and wait
  3. No preemption
  4. Circular wait

Prevention: break any one — consistent lock ordering, timeouts, lock all at once. Producer-Consumer: mutex + full + empty semaphores.

5. Virtual Memory & Paging

  • Each process gets a virtual address space mapped via page tables. Benefits: isolation, protection, larger-than-RAM.
  • Paging: fixed 4KB pages. Page fault: page not in RAM → load from disk (demand paging).
  • TLB: small cache of recent translations.
  • Fragmentation: external (scattered free holes) vs internal (wasted space inside blocks).
  • General OS vs RTOS: Linux = complex timeslice scheduling, virtual memory/MMU, MB-GB. FreeRTOS = deterministic priority preemption, no MMU/MPU only, KB.

8. Toolchain & Cross-Compilation (critical for embedded)

Steps: preprocess → compile → assemble → link.

gcc -E main.c          # preprocess only
gcc -S main.c          # assembly output
gcc -c main.c          # compile to object (main.o)
gcc -o prog main.o util.o -lm   # link
gcc -O2 -Wall -Wextra -g main.c -o prog
gcc -static -march=mips32r2 -DDEBUG
  • Cross-compiler: runs on x86, produces binaries for target (mips-linux-gnu-gcc, arm-linux-gnueabihf-gcc, aarch64-linux-gnu-gcc).
  • Triplet: <arch>-<vendor>-<os>-<abi>.
  • Static linking: code copied in, self-contained, bigger. Dynamic: links against .so at runtime, smaller, needs libs present.
  • Tools: objdump (disassemble), readelf (ELF headers), nm (symbols), strip, objcopy (raw binary for flashing), file (verify arch).

Makefile example

CC=gcc
CFLAGS=-Wall -O2
TARGET=hello
$(TARGET): main.o util.o
	$(CC) -o $@ main.o util.o
main.o: main.c
	$(CC) $(CFLAGS) -c main.c
clean:
	rm -f *.o $(TARGET)

9. Linux Kernel & Device Drivers

  • User vs kernel space: apps call the kernel via syscalls; drivers exposed as /dev/xxx; procfs/sysfs (/proc, /sys).
  • Driver types: Character (byte stream: UART, GPIO, keyboard) · Block (fixed-size: flash, eMMC, SD) · Network (packet: Ethernet, WiFi).
  • Modules: insmod / rmmod / lsmod / dmesg.
  • copy_to_user / copy_from_user: validated user↔kernel data transfer.
  • Device tree (.dts → .dtb): compatible, reg (base+size), interrupts — how the kernel knows about hardware.
  • Register access in drivers: ioremap + readl/writel.
void __iomem *base;
base = ioremap(0x1f000000, 0x1000);
writel(0x1, base + 0x14);
uint32_t v = readl(base + 0x00);
iounmap(base);

11. OS Flashcard Essentials

Process vs thread?

Process = own address space, PCB, heavy switch, isolated. Thread = shares memory, cheap switch.

Round robin vs priority?

RR gives each process a fixed time slice in a cycle (fair, good response). Priority runs highest-priority ready process (may starve → aging).

Mutex vs semaphore?

Mutex has ownership + priority inheritance, exclusive access. Semaphore is a counter for signaling/counting resources.

Deadlock 4 conditions?

Mutual exclusion, hold-and-wait, no preemption, circular wait. Prevent by breaking one (lock ordering).

What is a system call? Examples?

The API from user to kernel (open, read, write, fork, exec). Kernel performs privileged work.

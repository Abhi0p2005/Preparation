MEMORY MASTERY — COMPLETE

The single most-asked embedded topic. C memory layout, stack vs heap, pointers, alignment/padding, caches, virtual memory, MCU memory, MMIO, bugs, debugging, endianness.

1. Memory Hierarchy & Types

                    Speed        Size         Cost
Registers          fastest      ~100s bytes   highest/bit
L1/L2 Cache        2-10 cycles  KB-MB
Main RAM           100+ cycles  MB-GB
Flash/Disk         slowest      GB-TB         lowest/bit
  • Temporal locality — recently used data used again soon (loops). Spatial locality — nearby data (arrays). Caches exploit both.
  • Volatile vs non-volatile: SRAM/DRAM/registers = volatile; Flash/EEPROM/ROM = non-volatile.
  • RAM: SRAM (flip-flops, fast, no refresh, low density → cache, MCU RAM) vs DRAM (cap+transistor, refresh, high density → main RAM).
  • Flash: erased before writing, block/sector erase, limited endurance (~10k–100k cycles) → wear-leveling. NOR = byte-addressable, XiP, code. NAND = page-based, dense, storage.
  • Cache line — fixed-size block (32–64 bytes) moved RAM↔cache.

Modifying a string literal through a char* = UB (may crash). Startups: copy .data, zero .bss, set SP, call main.

3. Stack Deep Dive

  • LIFO region for: locals, function args, return addresses, saved registers (callee-saved). Grows downward; SP tracks top.
  • Function call frame: return address + saved prev SP/FP + args + locals pushed; popped on return.
  • Stack overflow: unbounded recursion or huge local arrays → collides with heap/bounds. MCU defenses: watchdog, stack boundary checks, linker --stack limits, stack canary (known value that detects overwrite).
  • Rules: keep locals small (big buffers → static/heap); avoid unbounded recursion in embedded.

4. Heap & Dynamic Memory

malloc(n)      // n bytes, uninitialized
calloc(n,sz)   // n*sz bytes, zeroed
realloc(p,n)   // resize (may MOVE — data preserved up to min)
free(p)        // release; ALWAYS p = NULL after
  • How malloc works: free-list search (first/best fit) → write header (size, flags) before returned pointer → return usable memory.
  • External fragmentation — free space total but scattered in small holes → big malloc fails. Internal fragmentation — allocated block bigger than asked (alignment/size-class rounding).
  • Why embedded hates malloc: non-deterministic timing, fragmentation over uptime, exhaustion, header overhead.
  • Memory pool — pre-partitioned fixed-size blocks → deterministic O(1), no fragmentation.

5. Pointers — Every Question

  • &x address · *p dereference · int **pp pointer-to-pointer (change a pointer in a function, 2D) · void * generic.
  • Pointer arithmetic scales by sizeof(type): p+1 for int* advances 4 bytes. char* moves 1 byte (byte walks / memcpy).
  • Null = points to 0 (segfault on deref). Dangling = points to freed memory (use-after-free). Wild = never initialized.
  • Never return a pointer to a local — dangling. Return static/global/heap.
  • Function pointers in embedded: callbacks, ISR tables, state-machine actions.

6. Alignment, Padding, sizeof

struct A { char c; int i; };   // sizeof 8 (c at 0, pad 1-3, i at 4)
struct B { char c; int i; char d; };  // 12 (two pad blocks)
struct C { char c; char d; int i; };  // 8  — reorder largest→smallest saves!
union U { char c; int i; };          // sizeof 4 (max member, aligned to int)
#pragma pack(1) ... #pragma pack()   // packed wire/protocol structs (slower, unaligned)

// bit fields
struct Ctrl { uint8_t en:1, mode:3, rd:1; };  // still sizeof 1
  • Why padding: hardware reads aligned addresses efficiently — compiler aligns members to natural boundaries.
  • sizeof(arr) = total array bytes; sizeof(ptr) = pointer size (4/8). strlen = runtime, excludes '\0'.
  • Offsetof trick: (size_t)&((type*)0)->member.

7. Caches

TypeMappingPros/Cons
Direct-mappedeach addr → exactly one slotsimple; conflict thrashing
Fully associativeany addr → any slotno conflicts; complex/expensive
Set-associative (N-way)one slot from a set of Nbalance — most real caches
  • Three C's of misses: Compulsory (cold, first access) · Capacity (working set > cache) · Conflict (addresses fight for same slot).
  • I-cache vs D-cache: separate → parallel fetch, no structural conflict (modified Harvard in MIPS/DSP).
  • Cache coherency with DMA (the embedded trap): two cores / CPU+DMA may hold stale copies. Write-back cache: flush before DMA reads; invalidate after DMA writes. Linux dma_map_single does this.

8. Virtual Memory, Paging, TLB, MMU

  • Each process gets a private virtual address space; the MMU translates virtual→physical via page tables. Benefits: isolation, protection, map more than physical RAM.
  • Paging: fixed 4KB pages; page table: page#→frame# with permission bits. Page fault = non-resident access → trap to kernel → load (demand paging) or kill (invalid).
  • TLB — small cache of recent translations (mirrors cache hit/miss). Large pages = fewer entries needed.
  • Fragmentation: internal in paging (last partial page); external in segmentation.
  • MMU — full virtual translation + protection + paging (Linux). MPU — no translation, only region-based permission/bounds (RTOS MCUs).

9. Embedded MCU Memory

0x0000_0000 - Flash      (code, .rodata)
0x2000_0000 - SRAM       (data, bss, heap, stack)
0x4000_0000 - Peripherals (APB/AHB: GPIO, UART...)
0xE000_0000 - System/private (NVIC, SysTick, MPU, debug)
  • Boot: vector table (initial SP, Reset_Handler) → copy .data (flash→SRAM) → zero .bss → init clocks/stack → main().
  • Flash: code XiP; endurance ~10k–100k; EEPROM ~100k–1M; write in bulk + wear-leveling.
  • Minimize SRAM: use const → push to flash. Watch stack vs heap overlap (linker).

10. Memory-Mapped I/O & DMA

#define GPIO_ODR (*(volatile uint32_t *)0x40020014)
GPIO_ODR |= (1 << 5);       // set output pin 5
  • Peripherals appear as memory addresses — read/write them like normal memory.
  • Why volatile is mandatory: register value changes outside program control (hardware/ISR/DMA); without volatile the compiler may cache a stale value or optimize away the access.
  • Bus: Data (values), Address (which register), Control (read/write/clock). SoC: AXI/AHB (high-speed, DMA) + APB (low-speed peripherals).
  • DMA — moves data memory↔peripheral WITHOUT CPU. CPU sets source/dest/count, gets interrupt when done.

15. Memory Interview Q&A Bank (master these)

Memory layout of a C program?

text (code) / rodata (consts) / data (init globals, copied at boot) / bss (zero globals) / heap (up) / stack (down).

.data vs .bss?

.data = initialized globals (copied from flash at boot). .bss = zeroed globals, no binary storage.

Stack vs heap?

Stack: LIFO, local frames, fast, fixed size, grows down, auto lifetime. Heap: malloc, manual lifetime, slower, may fragment.

Why does deep recursion crash?

Each call pushes a frame; unbounded recursion exhausts the fixed stack → stack overflow.

Why avoid dynamic allocation in embedded?

Determinism, fragmentation, exhaustion. Use static/pools.

Null vs dangling vs wild pointer?

0 vs freed memory vs uninitialized/garbage.

Why padding?

Alignment to natural boundaries for efficient hardware access.

Cache hit vs miss?

Hit = found (fast). Miss = fetch block from RAM (slow), may evict a line.

Why flush/invalidate cache with DMA?

CPU and DMA can hold different views of the same memory. Flush writes dirty lines; invalidate drops stale lines.

MMU vs MPU?

MMU = translation + protection + paging. MPU = protection-only regions (no translation).

What is a memory pool?

Pre-partitioned fixed-size blocks → O(1), deterministic, no fragmentation.

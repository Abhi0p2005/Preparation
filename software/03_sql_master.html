SQL MASTER GUIDE — ZERO TO WINDOW FUNCTIONS

Complete SQL from SELECT to window functions, joins, CTEs, subqueries, worked examples + flashcards.

1. SQL Statement Types

TypeNameExamplesPurpose

Trap: TRUNCATE is DDL (drops-and-recreates, no rollback). DELETE is DML (removes rows, rollback-able, fires triggers).

Key one-line definitions

  • Primary Key — uniquely identifies a row (no dup, no NULL)
  • Foreign Key — references another table's PK → relationship
  • Index — sorted lookup structure making WHERE fast (B-tree, O(log n))
  • Join — combine rows on a related column
  • Transaction — group of SQL that all succeed or all fail
  • Normalisation — split data into tables to avoid repetition

2. SELECT / WHERE / NULL / ORDER BY / LIMIT

SELECT * FROM trades;
SELECT DISTINCT asset_class FROM trades;
SELECT * FROM trades WHERE status='SETTLED' AND amount>100000;
SELECT * FROM trades WHERE amount BETWEEN 50000 AND 200000;   -- inclusive both ends
SELECT * FROM trades WHERE asset_class IN ('EQUITY','FX');
SELECT * FROM trades WHERE name LIKE '%BANK%';   -- % any, _ one char
SELECT * FROM trades WHERE settlement_date IS NULL;
SELECT * FROM trades ORDER BY amount DESC LIMIT 10;
SELECT trade_id AS id, amount*0.01 AS commission FROM trades;
  • Execution order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT. That's why aliases can't be used in WHERE but CAN in ORDER BY.
  • NULL is 3-valued logic (TRUE/FALSE/UNKNOWN): = NULL never true → use IS NULL. NULL = NULL is UNKNOWN.
  • COUNT(*) counts all rows (incl. NULLs) · COUNT(col) counts non-NULL · COUNT(DISTINCT col) counts distinct non-NULL.
  • BETWEEN is inclusive. AND binds tighter than OR — use parentheses.
  • Second-highest: SELECT DISTINCT salary ORDER BY salary DESC LIMIT 1 OFFSET 1; or MAX(salary) WHERE salary < (SELECT MAX(salary)).
  • Avoid SELECT * — pulls unused columns, breaks on schema change, can't use covering index.

3. GROUP BY & Aggregation

SELECT asset_class, SUM(amount) AS volume FROM trades GROUP BY asset_class;
SELECT asset_class, direction, COUNT(*) AS cnt FROM trades GROUP BY asset_class, direction;
SELECT counterparty, SUM(amount) AS volume FROM trades
WHERE status='SETTLED' GROUP BY counterparty HAVING SUM(amount) > 100000;

-- Conditional aggregation (one pass)
SELECT asset_class,
  COUNT(*) AS total,
  COUNT(CASE WHEN direction='BUY' THEN 1 END) AS buys,
  SUM(CASE WHEN status='FAILED' THEN amount ELSE 0 END) AS failed_amount
FROM trades GROUP BY asset_class;

Golden rule (#1 trap): every column in SELECT must be grouped OR inside an aggregate. WHERE filters rows (before grouping, no aggregates); HAVING filters groups (after, aggregates allowed). You can NEVER use an aggregate in WHERE.

  • Aggregates: COUNT, SUM, AVG, MIN, MAX. Without GROUP BY the whole table = one group.
  • GROUP BY NULL → NULLs form their own group.
  • DISTINCT vs GROUP BY: same unique rows; GROUP BY additionally enables aggregates.

4. JOINs

SELECT t.trade_id, t.amount, c.name FROM trades t
INNER JOIN counterparties c ON t.counterparty_id = c.id;

SELECT c.name, t.trade_id FROM counterparties c
LEFT JOIN trades t ON c.id = t.counterparty_id;   -- all left rows + matches

-- Find "no trades": LEFT JOIN + WHERE right col IS NULL
SELECT c.name FROM counterparties c
LEFT JOIN trades t ON c.id=t.counterparty_id
WHERE t.trade_id IS NULL;   -- CORRECT

-- SELF JOIN (hierarchy)
SELECT e.name AS employee, m.name AS manager
FROM employees e LEFT JOIN employees m ON e.manager_id=m.id;
  • Visual: INNER = A∩B · LEFT = A ∪ (A∩B) · RIGHT = (A∩B) ∪ B · FULL = A∪B · CROSS = A×B
  • LEFT JOIN trap: filtering the RIGHT table's column in WHERE converts it back to INNER JOIN — move that filter into the ON clause to keep unmatched rows.
  • INNER JOIN can multiply rows when right side has duplicates → use COUNT(DISTINCT) or a subquery.
  • JOIN vs UNION: JOIN merges columns sideways on a key; UNION stacks rows vertically (same column count).
  • Internal strategies: Nested Loop (tiny side), Hash Join (big equi-join), Merge Join (sorted).

5. String & Date Functions

CONCAT(a,b) | a || b (PG) | SUBSTRING(s FROM 1 FOR 4) | SUBSTR(s,1,4) (MySQL)
LENGTH(s) | CHAR_LENGTH(s) | UPPER() | LOWER() | TRIM() | LTRIM() | RTRIM()
REPLACE(phone,'-','') | LEFT(iban,4) | RIGHT(name,4) | REVERSE(s)

EXTRACT(YEAR FROM trade_date) | CURRENT_DATE | CURRENT_TIMESTAMP
trade_date + INTERVAL '2 days' (PG) | DATE_ADD(trade_date,INTERVAL 2 DAY) (MySQL)
DATEADD(day,2,trade_date) (SQLServer) | DATEDIFF(day,a,b)
DATE_TRUNC('month', trade_date) (PG) | DATE_FORMAT(trade_date,'%Y-%m') (MySQL)

Group-by-month pattern: truncate to a month boundary then GROUP BY. Index tip: WHERE trade_date BETWEEN '2026-01-01' AND '2026-12-31' is index-friendly; wrapping the column in EXTRACT kills the index. Postgres 'a'||NULL=NULL; MySQL CONCAT skips NULLs.

6. Subqueries & CTEs

-- Scalar subquery (per output row)
SELECT trade_id, amount, amount/(SELECT AVG(amount) FROM trades) FROM trades;

-- IN subquery
SELECT name FROM counterparties
WHERE id IN (SELECT counterparty_id FROM trades WHERE amount>1000000);

-- Correlated subquery (runs per outer row — "trades above their own asset-class avg")
SELECT trade_id, asset_class, amount FROM trades t
WHERE amount > (SELECT AVG(amount) FROM trades WHERE asset_class=t.asset_class);

-- EXISTS short-circuits (faster for big sets)
SELECT c.name FROM counterparties c WHERE EXISTS
  (SELECT 1 FROM trades t WHERE t.counterparty_id=c.id AND t.amount>1000000);

-- Derived table in FROM must have an alias
SELECT * FROM (SELECT asset_class, AVG(amount) a FROM trades GROUP BY asset_class) s WHERE a>50000;

-- CTE (named, reusable, chained)
WITH high AS (SELECT counterparty_id, SUM(amount) v FROM trades WHERE status='SETTLED'
              GROUP BY counterparty_id HAVING SUM(amount)>10000000)
SELECT c.name, h.v FROM counterparties c JOIN high h ON c.id=h.counterparty_id;

-- Recursive CTE (org hierarchy): anchor + UNION ALL + recursive member
WITH RECURSIVE org AS (
  SELECT id,name,manager_id,1 AS lvl FROM employees WHERE manager_id IS NULL
  UNION ALL
  SELECT e.id,e.name,e.manager_id,ot.lvl+1 FROM employees e
  JOIN org ot ON e.manager_id=ot.id)
SELECT * FROM org;

NOT IN + NULL trap: x NOT IN (1,2,NULL) is never TRUE → returns zero rows. Fix: use NOT EXISTS or filter NULLs.

  • IN vs EXISTS: EXISTS short-circuits at first match (fast for large subqueries).
  • Subquery in SELECT must be scalar (one row, one column).
  • CTE vs temp table: CTE lives only for the query; temp table persists across statements.
  • Recursive CTE needs 3 parts: anchor + UNION ALL + recursive member that joins back.

7. Window Functions (the game-changer)

-- ROW_NUMBER / RANK / DENSE_RANK
SELECT trade_id, amount,
  ROW_NUMBER() OVER (ORDER BY amount DESC) rn,
  RANK()       OVER (ORDER BY amount DESC) rk,
  DENSE_RANK() OVER (ORDER BY amount DESC) drk
FROM trades;
-- amounts [100,80,80,50]: ROW=1,2,3,4 · RANK=1,2,2,4 · DENSE=1,2,2,3

-- Top-N per category (the most reused idiom)
SELECT * FROM (SELECT trade_id, amount,
  DENSE_RANK() OVER (PARTITION BY asset_class ORDER BY amount DESC) rnk
  FROM trades WHERE status='SETTLED') x WHERE rnk<=3;

-- LAG / LEAD (previous / next row) for MoM / day-over-day change
SELECT trade_date, SUM(amount) v,
  LAG(SUM(amount)) OVER (ORDER BY trade_date) prev,
  SUM(amount)-LAG(SUM(amount)) OVER (ORDER BY trade_date) chg
FROM trades GROUP BY trade_date ORDER BY trade_date;

-- Running total (default frame: UNBOUNDED PRECEDING TO CURRENT ROW)
SELECT trade_date, amount,
  SUM(amount) OVER (PARTITION BY counterparty_id ORDER BY trade_date) running
FROM trades;

-- Rolling average (7-row frame)
AVG(amount) OVER (ORDER BY txn_ts ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)

Window vs GROUP BY: GROUP BY collapses rows to one per group. Window functions keep EVERY row and ADD a computed value over a window. Every window needs OVER(). To filter a window result use a subquery/CTE (WHERE rn=1 fails directly).

8. UNION / INTERSECT / EXCEPT

SELECT city FROM a UNION SELECT city FROM b;       -- dedup (slower, sorts)
SELECT city FROM a UNION ALL SELECT city FROM b;   -- keeps dups (faster)
SELECT id FROM a INTERSECT SELECT id FROM b;       -- both (not in MySQL → IN subquery)
SELECT id FROM a EXCEPT SELECT id FROM b;          -- a minus b (not in MySQL → NOT IN / LEFT JOIN IS NULL)

Rules: same column count, compatible types, aligned order. Column names come from the first SELECT.

9. Must-Know Patterns (DS/SQL interviews)

  • Dedup keep-latest-per-key: ROW_NUMBER() OVER (PARTITION BY key ORDER BY ts DESC) = 1, or GROUP BY + MAX(ts) + join.
  • MoM % change: LAG(metric) OVER (ORDER BY month), then (cur − prev)/prev with NULLIF.
  • Top-N per group: ROW_NUMBER() OVER (PARTITION BY group ORDER BY metric DESC) = 1.
  • Cohort retention: COUNT(DISTINCT user_id) per signup-week + SUM(CASE WHEN re-active...).
  • Funnel: COUNT(CASE WHEN step='OPEN' THEN 1 END) per stage per user.
  • Date helpers: DATE_TRUNC('month', ts), EXTRACT(YEAR FROM ts), DATEDIFF.
  • NULLIF for division: x / NULLIF(y, 0) — returns NULL instead of dividing by zero.
  • COALESCE(a, b, 0): first non-NULL value.

10. Worked Example — MAU + MoM % change

WITH mau AS (
  SELECT DATE_TRUNC('month', txn_ts) AS month,
         COUNT(DISTINCT user_id)     AS active_users
  FROM txns WHERE status = 'success'
  GROUP BY DATE_TRUNC('month', txn_ts)
)
SELECT month, active_users,
       ROUND(100.0 * (active_users - LAG(active_users) OVER (ORDER BY month))
             / NULLIF(LAG(active_users) OVER (ORDER BY month), 0), 2) AS mom_change_pct
FROM mau ORDER BY month;

Why it scores: COUNT(DISTINCT user_id) not COUNT(*); LAG over the monthly window; NULLIF guards the first row (MoM undefined → NULL, correct).

13. SQL Flashcard Essentials

Logical execution order?

FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT.

WHERE vs HAVING?

WHERE filters ROWS before grouping (no aggregates). HAVING filters GROUPS after grouping (aggregates allowed).

ROW_NUMBER vs RANK vs DENSE_RANK?

ROW_NUMBER = unique even on ties. RANK = ties share, numbers skip (1,1,3). DENSE_RANK = ties share, no skip (1,1,2).

Why can't you use a SELECT alias in WHERE?

WHERE runs before SELECT creates the alias. Use HAVING, subquery, or repeat the expression.

MySQL vs Postgres default isolation?

MySQL = Repeatable Read. Postgres = Read Committed.

NOT IN + NULL trap?

x NOT IN (1,2,NULL) is never TRUE → returns nothing. Fix: NOT EXISTS or filter NULLs.

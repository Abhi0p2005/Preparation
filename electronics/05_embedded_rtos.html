Which is fastest? SPI — synchronous full-duplex, no addressing overhead. I2C is addressed (slower, half-duplex). UART is asynchronous (needs matched baud).

  • UART: 2-wire async, baud must match, full-duplex. SPI: 4-wire sync, full-duplex, master/slave with CS. I2C: 2-wire, open-drain + pull-ups, addressed, half-duplex.
  • CAN: differential CAN_H/CAN_L, dominant (0) / recessive (1) bits, arbitration by priority, up to 1 Mbps, used in automotive ECUs.

3. Interrupts & ISR

  • Interrupt — external hardware event → CPU jumps to ISR. Exception — internal event (div by zero, invalid instruction).
  • Flow: save context → jump to interrupt vector → ISR runs → return (eret/rti). MIPS: Cause/Status/EPC registers.
  • Golden rule: minimal work in ISR — set a flag / push to a queue / signal a task. Heavy work in main loop or a task. NO printf/malloc in ISR.
  • Interrupt enable/mask registers (IER); priority/vector tables; nesting.
volatile uint8_t g_event = 0;
void ISR_Handler(void){ g_event = 1; }        // minimal work
int main(void){ for(;;){ if(g_event){ g_event=0; do_work(); } } }

4. ARM Cortex-M Boot Sequence

0x00000000 = initial SP
0x00000004 = Reset_Handler address
Reset: → copy .data (flash→SRAM) → zero .bss → SystemInit (clocks)
     → call main()
  • Vector table at address 0: entry 0 = initial stack pointer, entry 1 = reset handler.
  • Then .data copy, .bss zeroing, clock init, main().

5. Watchdog & DMA

  • Watchdog timer — hardware timer that resets the MCU if the software stops kicking it (detects hangs / infinite loops). Firmware must periodically refresh it.
  • DMA — transfers data between peripheral and memory without CPU. CPU sets source/dest/count, gets an interrupt when done. Frees CPU for other work.

6. Real-Time Systems & FreeRTOS

Hard vs soft real-time

  • Hard real-time: missing deadline = failure (airbag, motor control). Soft: degrades quality (video).
  • Determinism: predictable, bounded worst-case timing.

FreeRTOS tasks & scheduler

void vTask1(void *p){ for(;;){ toggle_led(); vTaskDelay(pdMS_TO_TICKS(500)); } }
xTaskCreate(vTask1, "Task1", 128, NULL, 1, NULL);   // priority 1
xTaskCreate(vTask2, "Task2", 128, NULL, 2, NULL);   // priority 2 (higher = more important)
vTaskStartScheduler();
  • Preemptive priority scheduling: highest-priority READY task runs. Timer interrupt (tick) drives the scheduler. Equal priorities → time slicing (round-robin).
  • Task states: Running, Ready, Blocked (waiting on delay/event/queue), Suspended.
  • Context switch: save current task's registers + stack, load next task's.

7. FreeRTOS Synchronization & Communication

// Queue — THE way to pass data between tasks and ISRs
QueueHandle_t q = xQueueCreate(10, sizeof(uint32_t));
xQueueSend(q, &val, portMAX_DELAY);
xQueueReceive(q, &val, portMAX_DELAY);

// Binary semaphore — signaling (ISR → task)
SemaphoreHandle_t s = xSemaphoreCreateBinary();
xSemaphoreTake(s, portMAX_DELAY);       // wait for signal

// Counting semaphore — N resources
SemaphoreHandle_t c = xSemaphoreCreateCounting(10, 0);

// Mutex — mutual exclusion, has PRIORITY INHERITANCE
SemaphoreHandle_t m = xSemaphoreCreateMutex();
xSemaphoreTake(m, portMAX_DELAY);  ...  xSemaphoreGive(m);

// Event groups
xEventGroupSetBits(eg, BIT0);
xEventGroupWaitBits(eg, BIT0|BIT1, pdTRUE, pdTRUE, portMAX_DELAY);

// Software timers
xTimerCreate("t", pdMS_TO_TICKS(1000), pdTRUE, NULL, cb); xTimerStart(t,0);

ISR ↔ task (must use FromISR versions)

void ISR_Handler(void){
  BaseType_t hpw = pdFALSE;
  uint8_t byte = read_uart();
  xQueueSendFromISR(q, &byte, &hpw);
  portYIELD_FROM_ISR(hpw);   // reschedule if a task was unblocked
}

8. Priority Inversion & Priority Inheritance

  • Priority inversion: a low-priority task holds a resource a high-priority task needs, while medium-priority tasks run and starve the high task.
  • Fix: priority inheritance (mutex) — the low task temporarily inherits the high task's priority, so it can't be preempted by mediums.
  • Binary semaphores usually don't support priority inheritance; mutexes do (most RTOS).

9. FreeRTOS Memory & Best Practices

  • heap_1..heap_5 (see Memory page 4 §13). heap_4 (coalesces) is the best general choice.
  • Overflow detection: configCHECK_FOR_STACK_OVERFLOW == 1 or 2.
  • Static allocation preferred (configSUPPORT_DYNAMIC_ALLOCATION=0) for determinism.
  • Never malloc/printf in ISR. Use FromISR APIs.

#define GPIO_ODR  (*(volatile uint32_t *)(GPIO_BASE + 0x14))
void led_on(void){ GPIO_ODR |= (1<<5); }

// circular buffer
push: if(count==SIZE) return -1; buf[head]=c; head=(head+1)%SIZE; count++;
pop:  if(count==0) return -1; *c=buf[tail]; tail=(tail+1)%SIZE; count--;

// state machine
typedef enum {RED,GREEN,YELLOW} Light;
Light next(Light cur){ switch(cur){ case RED: return GREEN; ... } }

// linked list push-front + traverse
node_t *n = malloc(sizeof(node_t)); n->data=5; n->next=head; head=n;
for(node_t *p=head; p; p=p->next) printf("%d ", p->data);

// UART putc (polled)
void uart_putc(uint32_t base, char c){
  volatile uint32_t *reg = (volatile uint32_t*)base;
  while(!(reg[LSR] & 0x20));   // wait TX empty
  reg[DR] = c; }

11. Embedded Interview Q&A

Best practice inside an ISR?

Keep it short, fast, non-blocking. Set a flag / copy to buffer / signal a task; do the work in main.

What does a watchdog do?

Resets the MCU if software stops kicking it — recovers from hangs.

Semaphore vs mutex?

Semaphore signals/limits resources (no ownership). Mutex provides exclusive access with ownership + priority inheritance.

What is priority inversion? Fix?

Low task holds a mutex a high task needs while mediums starve the high task. Fix: priority inheritance.

What is DMA for?

Transfers data between peripheral and memory without CPU involvement.

How do ISR and task communicate?

Via queues / binary semaphores using ...FromISR APIs; yield after giving.

What is the tick?

A periodic timer interrupt that drives the scheduler (configTICK_RATE_HZ, e.g. 1 kHz = 1 ms).

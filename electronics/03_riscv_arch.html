RISC-V + MIPS + VERILOG

Registers, instruction formats, instructions, pipeline hazards, immediate extraction, ALU, MIPS assembly, Verilog/SV — for digital design & semiconductor OAs.

1. Computer Architecture Basics

  • A computer: Input → Process → Store → Output. CPU = ALU + CU + Registers.
  • Von Neumann: one memory for code+data, single bus (bottleneck). Harvard: separate code/data memories, parallel buses → used in many MCUs (PIC, AVR, DSP). MIPS SoCs often use modified Harvard (separate I-cache/D-cache).
  • Fetch–Decode–Execute cycle: fetch instruction from PC → decode in CU → execute in ALU → advance PC → repeat.
  • Registers: PC (next instruction), IR (current instruction), SP (stack), general purpose, status/flags (zero, carry, overflow, negative).
  • RISC vs CISC: RISC = simple fixed-length, load-store (MIPS, ARM, RISC-V); CISC = complex variable-length, ops can touch memory (x86).
  • Memory hierarchy: Registers (~1 cycle) → L1/L2 cache (2–10) → RAM (100+) → Disk (millions). Locality: spatial (nearby) + temporal (recent).

3. RISC-V Instruction Formats (all 32-bit, 6 types)

  • R-type: funct7(7) rs2(5) rs1(5) funct3(3) rd(5) opcode(7) → ADD rd,rs1,rs2
  • I-type: imm[11:0] rs1 funct3 rd opcode → ADDI, LW
  • S-type: imm[11:5] rs2 rs1 funct3 imm[4:0] opcode → SW
  • B-type: imm[12] imm[10:5] rs2 rs1 funct3 imm[4:1] imm[11] opcode → BEQ (imm[0]=0)
  • U-type: imm[31:12] rd opcode → LUI
  • J-type: imm[20] imm[10:1] imm[11] imm[19:12] rd opcode → JAL

All immediates are sign-extended (except U). B & J type have LSB = 0 (aligned to 2 bytes). I-type imm[0] exists.

Immediate extraction (expect coding in Verilog)

wire [31:0] imm_i = {{21{instruction[31]}}, instruction[30:20]};
wire [31:0] imm_s = {{21{instruction[31]}}, instruction[30:25], instruction[11:7]};
wire [31:0] imm_b = {{20{instruction[31]}}, instruction[7], instruction[30:25], instruction[11:8], 1'b0};
wire [31:0] imm_u = {instruction[31:12], 12'b0};
wire [31:0] imm_j = {{12{instruction[31]}}, instruction[19:12], instruction[20], instruction[30:21], 1'b0};

LUI rd, imm        → rd = imm << 12
AUIPC rd, imm      → rd = PC + (imm << 12)

5. The 5-Stage Pipeline

IF → ID → EX → MEM → WB
1: IF (fetch, PC+4)
2: ID (decode, read rs1/rs2, sign-extend)
3: EX (ALU, branch check, effective address)
4: MEM (D$ read for LW / write for SW)
5: WB (write result to rd)

Pipeline registers: IF/ID (PC, instr), ID/EX (PC, rs1_val, rs2_val, imm, control), EX/MEM (ALU result, rs2_val, rd), MEM/WB (mem data, ALU result, rd).

6. Pipeline Hazards

Structural

Two instructions need the same hardware unit (single memory for I$ + D$ on load). Fix: separate I$/D$ (Harvard) or stall.

Data Hazard (RAW)

ADD x1, x2, x3    // x1 written in WB
SUB x4, x1, x5    // x1 read in EX — stale!
→ Fix: FORWARDING (bypass) from EX/MEM or MEM/WB to EX input mux

Load-Use Hazard

LW x1, 0(x2)      // x1 ready at END of MEM
ADD x3, x1, x4    // x1 needed at START of EX
→ Requires 1 STALL BUBBLE + forward

Control Hazard (Branch)

Branch decided in EX → next PC unknown until cycle 3. Fix: predict-not-taken (flush 2 stages on miss), branch target buffer, 2-bit saturating counter. Penalty = 2 cycles if mispredicted.

7. ALU in Verilog

module riscv_alu(input logic [31:0] a,b, input logic [3:0] alu_op,
                 output logic [31:0] out, output logic zero);
  always_comb case(alu_op)
    4'b0000: out = a + b;     // ADD
    4'b0001: out = a - b;     // SUB
    4'b0010: out = a & b;     // AND
    4'b0011: out = a | b;     // OR
    4'b0100: out = a ^ b;     // XOR
    4'b0101: out = a << b[4:0];   // SLL
    4'b0110: out = a >> b[4:0];   // SRL
    4'b0111: out = $signed(a) >>> b[4:0]; // SRA
    4'b1000: out = ($signed(a) < $signed(b)); // SLT
    4'b1001: out = (a < b);   // SLTU
  endcase
  assign zero = (out == 32'b0);
endmodule

// forwarding mux control
if (ex_mem_regwrite && ex_mem_rd!=0 && ex_mem_rd==id_ex_rs1) fwd = 2'b10; // EX/MEM
else if (mem_wb_regwrite && mem_wb_rd!=0 && mem_wb_rd==id_ex_rs1) fwd=2'b01; // MEM/WB
else fwd = 2'b00;

8. Verilog / SystemVerilog Basics

  • module/endmodule; input/output; wire (continuous) vs reg (procedural).
  • always_comb (combinational, = blocking) vs always_ff @(posedge clk) (sequential, <= non-blocking).
  • Blocking (=) in combinational; non-blocking (<=) in sequential — the golden rule.
  • case, if/else, parameter/localparam, generate.
  • Branch (EX stage): BEQ zero=1, BNE zero=0, BLT lt=1, BGE lt=0.

9. MIPS Architecture (GlobalFoundries)

Registers (32 × 32-bit)

$zero(0)=0 · $v0-$v1(2-3)=return · $a0-$a3(4-7)=args · $t0-$t7(8-15)=caller-saved · $s0-$s7(16-23)=callee-saved · $t8-$t9(24-25) · $k0-$k1(26-27)=kernel · $gp(28) · $sp(29) · $fp(30) · $ra(31)

Instruction formats

  • R: op rs rt rd shamt funct → add, sub, and, or, slt
  • I: op rs rt immediate(16) → addi, lw, sw, beq, bne
  • J: op target(26) → j, jal

Common instructions

add $t0,$t1,$t2    # t0 = t1 + t2
addi $t0,$t1,100  # immediate
slt  $t0,$t1,$t2  # t0 = 1 if t1 < t2
lw $t0, 0($sp)    # load word
sw $t0, 4($sp)    # store word
beq $t0,$t1,L     # branch equal
j L               # unconditional jump
jal L             # jump-and-link ($ra = return address)
jr $ra            # return from function
li $t0,100 / move $t0,$t1   # pseudo-instructions

Translate C → MIPS

a = b + c;         → add $s0,$s1,$s2     (a=$s0,b=$s1,c=$s2)
if(x==y) goto L;   → beq $t0,$t1,L
a = b - c;         → sub $s0,$s1,$s2
a = b + 100;       → addi $s0,$s1,100
x = arr[i];        → lw $t0, offset($t1)
arr[i] = x;        → sw $t0, offset($t1)
if (a==b) c=d+1;   → bne $s0,$s1,skip; addi $s2,$s3,1; skip:

10. PC Calculation

pc_plus4      = pc + 4
branch_target = pc + imm_b
jump_target   = pc + imm_j
jalr_target   = (rs1 + imm_i) & ~1   // JALR clears LSB
if (branch_taken) next_pc = branch_target;
else if (jal) next_pc = jump_target;
